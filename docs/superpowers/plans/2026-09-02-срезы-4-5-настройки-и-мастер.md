# Срезы 4 и 5 «Настройки в сайдбаре» и «Мастер установки» — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Цель среза 4:** всё, что сейчас правится в двух файлах руками, правится в
сайдбаре: справочник статей на виду, белый список никнеймами, бот подключается

доходит до первой строки в таблице, не открыв ни одного файла. Результат для
группы — установка с нуля на чужом компьютере, в один заход.

## Почему два среза в одном плане

Это одна работа, увиденная дважды. Мастер задаёт движок, таблицу, телеграм и
белый список **в первый раз**; сайдбар меняет то же самое **потом**. Те же поля,
та же проверка значений, та же запись в `settings.json` и `.env`. Разложить их
по двум планам — значит написать одни и те же формы дважды и получить два
расходящихся набора текстов отказа для одной и той же ошибки.

**Поэтому сайдбар идёт первым, а мастер вторым и переиспользует его редакторы.**
Порядок в роадмапе (4, потом 5) при этом не нарушается — он такой же.

Что именно переиспользуется — не общее рассуждение, а список:

| Что | Появляется | Переиспользуется |
|---|---|---|
| `config.save_settings()`, `config.save_env()` | задача 1 | задачи 8, 9, 10 |
| `agent.versions()` и маршрут `/api/engines` | задача 2 | задача 8 — шаг «Движок» |
| `/api/telegram/check` и `/api/telegram/save` | задача 5 | задача 10 — шаг «Телеграм» |
| Впустить постучавшегося (`/api/people/allow`) | задача 3 | задача 10 — «это вы?» |
| Проверка таблицы числом статей | задача 9 | сайдбар показывает то же число |

## Граница между срезами

**Срез 4 — задачи 1–5.** Сдаётся отдельно: бот уже настроен, человек меняет
настройки в сайдбаре. Демонстрация группе — заменить бота при работающем опросе
и впустить коллегу, не открывая редактор.

**Срез 5 — задачи 6–10.** Сдаётся отдельно: пустая папка, мастер, первый чек.
Задача 10 — приёмка обоих срезов.

Задача 1 формально служит обоим и лежит в срезе 4 потому, что сайдбару она
нужна раньше: без записи `settings.json` не работает ни одна кнопка сайдбара.

## Границы

**Делаем.** Сайдбар: число статей у пункта «Таблица», белый список никнеймами
(впущенные с «Убрать», стучавшиеся с «Впустить»), подключение, замена и
отключение бота, переключатель движка. Мастер: три шага, третий необязательный;
движок, таблица, телеграм; `.env` и `settings.json` пишутся из браузера.

**Не делаем.** Правку последней записи (срез 3), редактирование справочника
статей, тёмную тему, прогон тестовых чеков кнопкой, месячную сводку, доступ
снаружи и вход по паролю, работу с нескольких компьютеров.

**Взято сверх разделов спеки, и почему:**

1. **Бот обязан стартовать без `.env` и без `settings.json`.** Сейчас
   `config.load_env()` делает `sys.exit`, если нет `SHEET_URL`. Пока это так,
   главная проверка среза 5 («пустая папка») не проходит физически: мастер
   некому показать. Задача 6.
2. **Токен бота правится и в сайдбаре, и в мастере.** Прямое требование
   владельца: репозиторий публичный, ученик разворачивает бота у себя и
   подключает своего. Задачи 5 и 10.
3. **Проверка белого списка переезжает в начало разбора.** Спека требует этого
   в разделе «Настройку меняют у работающего бота»; формально это не «Сайдбар»,
   но без неё кнопка «Убрать» обманывает: сообщение убранного человека,
   стоящее в очереди, разберётся и уедет в таблицу. Задача 3.

## Global Constraints

Требования, действующие во всех задачах без исключения.

- **Python 3.13**, венв в `.venv`. Запуск всегда `.venv/bin/python`, не `python`.
- **Зависимости ровно три:** `requests`, `python-dotenv`, `flask`. Ничего
  нового этот план не добавляет.
- **На клиенте ни одной библиотеки.** Обычный JS, без сборщиков и npm.
- **Только `127.0.0.1`.** Страница показывает токен бота и секрет таблицы,
  пароля у неё нет — доступ ограничен ровно тем, что адрес локальный. Ни
  `0.0.0.0`, ни внешнего адреса, ни туннелей.
- **Маршруты, ключи JSON и имена переменных — латиницей.** Кириллица едет
  только значениями внутри тела запроса. Причина не вкусовая: кириллица
  безопасна там, где она данные, и отказывает там, где её сравнивают по
  идентичности. В проекте это ловили трижды за один день, дважды молча —
  служебная ручка `/строки` не срабатывала никогда, потому что `curl` шлёт путь
  percent-кодированным; переменная шелла с кириллицей в имени всегда непуста, и
  крючок `pre-push` из-за этого пропускал всё. Роадмап, раздел Notes.
- **Тексты, докстринги и комментарии — русские**, и в питоне, и в JS.
- **Настройки читаются в начале каждой работы, а не запоминаются при старте.**
  Иначе любая правка в сайдбаре потребует перезапуска, а мы обещаем обратное.
  `config.load_settings()` уже зовётся перед каждым сообщением — так и
  оставляем; ни один новый кусок не имеет права закешировать `engine` или
  белый список у себя.
- **Настройка действует на то, что начнётся после неё, а не на то, что уже
  идёт.** Начатый разбор доводится прежним движком.
- **`settings.json` и `.env` пишутся только через `config`.** Ни `web.py`, ни
  `bot.py` не открывают эти файлы сами: иначе через месяц у нас будет три места,
  где пишется токен, и два из них без атомарности.
- **Пустой белый список — безопасное состояние.** Бот не отвечает никому.
  Испорченный `settings.json` не чинится записью поверх: сперва читаем, не
  прочиталось — не пишем.
- **`static/style.css` не трогаем.** Всё, что нужно обоим срезам, в нём уже
  есть: `.pick`, `.field`, `.fin`, `.code`, `.verdict`, `.wait`, `.pulse`,
  `.conseq`, `.att-box`, `.steps`, `.pips`. Не хватило класса — значит, экран
  расходится с эталоном, и правится экран, а не стили.
- **Эталон вёрстки — `design/workspace.html`.** Цвета, размеры, отступы,
  скругления, иконки — оттуда.
- **Терракота `#C4714F` значит «взгляни», и только это.** Точка «телеграм
  подключён» зелёная `#4E9A5A`.
- **Звёздочка Anthropic не используется.** Знак свой — кассовая лента.
- **Тёмной темы нет.** Первая версия светлая.
- **Числовой `chat_id` человек не видит никогда.** Ни в сайдбаре, ни в мастере,
  ни в подсказке. Бот работает по нему, показывает — ник или имя из профиля.
- **Секрет таблицы придумывает программа, а не человек.**
  `secrets.token_urlsafe(16)`. Придуманный человеком будет либо `12345`, либо
  забыт при вставке во второе место.
- **`sheet.gs` не правим.** Мастер читает его с диска и подставляет секрет
  вместо `__СЕКРЕТ__`. Заглушки в файле не нашлось — мастер обязан отказаться,
  а не показать ученику код с `__СЕКРЕТ__` внутри: такой код опубликуется и
  будет пускать любого, кто пришлёт слово `__СЕКРЕТ__` (`sheet-setup.md`,
  «Формат подстановки для программы установки»).
- **`allow_redirects` в запросах к Apps Script не отключать** — придёт пустой
  `302`. Наследие среза 1, к мастеру относится напрямую: он ходит в таблицу
  тем же `sheet.py`.
- **Автотестов нет.** Проверка живьём плюс `tools/selfcheck.py` на голых
  `assert` для чистых функций. Ни pytest, ни папки `tests/`.
- **Код — учебный материал.** Простые функции, русские докстринги, никаких
  дата-классов, аннотаций типов и абстракций сверх необходимого. Читателем
  будет финансист, впервые открывший питон.
- **Наследие срезов 1 и 2, которое нельзя нарушить:** у разбора один вход
  (`intake.accept()`); проверки без модели не спрашивают агента, уверен ли он;
  `--agent` не используется; `--json-schema` у Claude Code принимает текст
  схемы, а `--output-schema` у Codex — путь к файлу; пустой `structured_output`
  — отказ; статьи агенту придумывать нельзя; канала в таблице нет; своё не
  подписывается, чужое подписывается «имя · канал».

**Почему `setup.py` отдельным файлом, а не куском `web.py`.** Там две чистые

её» интереснее, чем маршрут. В `web.py` остаются маршруты и ничего больше — та

место никогда не открыты одновременно: `/` отдаёт либо одно, либо другое.
Общего кода у них меньше, чем кажется, — у мастера нет ни ленты, ни опроса
событий, ни перетаскивания. Слить их значит возить на каждый экран половину
чужого файла.

# Срез 4. Настройки в сайдбаре

### Задача 1: Программа пишет настройки, а не только читает

До сих пор `config.py` умел читать. Обе кнопки сайдбара и все три шага мастера
упираются в то, что записи нет. Начинаем с неё — и делаем один раз на оба среза.

**Файлы:**
- Править: `config.py`, `tools/selfcheck.py`
- Проверка: `.venv/bin/python tools/selfcheck.py`

**Стыки:**
- Берёт: `config.SETTINGS_PATH`, `config.BASE_DIR` — уже есть.
- Отдаёт: `config.save_settings(settings)`; `config.save_env(pairs)`;
  `config.patch_env_text(text, pairs)` → новый текст файла;
  `config.read_env()` → словарь с ключами `bot_token`, `sheet_url`,
  `sheet_secret`, `sheet_link`; `config.refresh_env(env)` → обновляет чужой
  словарь на месте.

- [ ] **Шаг 1: Завести замок и путь к `.env` в `config.py`**

Рядом с `SETTINGS_PATH`:


- [ ] **Шаг 2: Написать `save_settings()` в `config.py`**

```python
def save_settings(settings):
    """Пишет settings.json. Единственное место записи: ни web.py, ни bot.py
    этот файл сами не открывают — иначе через месяц мест будет три, и два из
    них без замка.

    Через временный файл: Ctrl+C посреди записи не должен оставить огрызок,
    из которого бот потом никого не впустит.

    resolve() здесь обязателен, и это не украшение. В рабочих деревьях
    (git worktree) settings.json и .env — символические ссылки на общие файлы.
    replace() по ссылке заменил бы саму ссылку обычным файлом: дерево тихо
    отвязалось бы от общих настроек и дальше правило свою копию, а человек
    узнал бы об этом через день, не найдя вчерашней правки. Разрешаем ссылку
    и пишем рядом с целью."""
    with _WRITE_LOCK:
        path = SETTINGS_PATH.resolve()
        tmp = path.with_name(path.name + ".tmp")
        tmp.write_text(json.dumps(settings, ensure_ascii=False, indent=2),
                       encoding="utf-8")
        tmp.replace(path)
```

- [ ] **Шаг 3: Написать `patch_env_text()` в `config.py`**

Чистая функция: текст на входе, текст на выходе. Её и проверяет самопроверка.

```python
def patch_env_text(text, pairs):
    """Новый текст .env: значения из pairs заменены, остальное как было.

    Файл правится построчно, а не собирается заново. Причина не в
    аккуратности: .env — не только машинная память, в нём комментарии,
    объясняющие человеку, что за строка и откуда её взять. Собрать файл
    заново значит стереть их, и следующий, кто откроет .env, увидит четыре
    голых ключа без единого слова.

    Строки с решёткой пропускаются целиком: в .env.example закомментированы
    примеры вида «# SHEET_URL=…», и без этой проверки мастер вписал бы адрес
    в пример, а настоящая строка осталась бы пустой.

    Ключа в файле не нашлось — строка дописывается в конец. Значение
    вписывается без кавычек: токен, адрес и секрет из secrets.token_urlsafe
    в них не нуждаются, а лишние python-dotenv вернёт как часть значения."""
    lines = text.splitlines()
    written = set()
    for number, line in enumerate(lines):
        if line.lstrip().startswith("#"):
            continue
        name = line.split("=", 1)[0].strip()
        if name in pairs:
            lines[number] = f"{name}={pairs[name]}"
            written.add(name)
    for name, value in pairs.items():
        if name not in written:
            lines.append(f"{name}={value}")
    return "\n".join(lines) + "\n"
```

- [ ] **Шаг 4: Написать `save_env()` и `read_env()` в `config.py`**

```python
def save_env(pairs):
    """Правит .env и тут же обновляет окружение процесса.

    Файла нет — берём за образец .env.example: в нём те же ключи и те же
    объяснения, ради которых файл и правится построчно. Нет и образца — пишем
    с пустого места. Пустая папка — обычный случай, а не поломка: ровно так
    ученик и начинает.

    os.environ обновляется здесь же, потому что python-dotenv читает файл один
    раз при старте и второй раз не станет. Без этой строки настройка легла бы
    на диск, а работающий бот продолжил бы жить со старым значением до
    перезапуска — ровно то, чего мы обещали не делать."""
    with _WRITE_LOCK:
        path = ENV_PATH.resolve()
        try:
            text = path.read_text(encoding="utf-8")
        except FileNotFoundError:
            example = BASE_DIR / ".env.example"
            text = example.read_text(encoding="utf-8") if example.exists() else ""
        tmp = path.with_name(path.name + ".tmp")
        tmp.write_text(patch_env_text(text, pairs), encoding="utf-8")
        tmp.replace(path)
    for name, value in pairs.items():
        os.environ[name] = value


def read_env():
    """Секреты из окружения словарём. Без проверок и без чтения файла —
    файл читает load_env(), а обновляет окружение save_env()."""
    return {
        "bot_token": os.getenv("BOT_TOKEN", "").strip(),
        "sheet_url": os.getenv("SHEET_URL", "").strip(),
        "sheet_secret": os.getenv("SHEET_SECRET", "").strip(),
        "sheet_link": os.getenv("SHEET_LINK", "").strip(),
    }


def refresh_env(env):
    """Обновляет чужой словарь env на месте, из окружения.

    Именно на месте, а не новым словарём. Этот словарь держат у себя все три
    потока — веб, опрос телеграма и разбор. Присвоить переменной новый словарь
    в одном месте значит оставить два потока со старым и потом полдня искать,
    почему бот ходит в прежнюю таблицу."""
    env.update(read_env())
```

- [ ] **Шаг 5: Свести `load_env()` к `read_env()`**

`load_env()` не переписываем целиком — правим в нём одно место. Блок `return {…}`
с четырьмя ключами заменяется на `return read_env()`. Всё остальное в функции —
`load_dotenv`, проверка `REQUIRED_ENV`, текст отказа — остаётся как есть,
вместе с комментариями. Проверка исчезнет в задаче 6, не здесь: сейчас мы

```python
# Ответ живёт минуту. Сайдбар опрашивает сервер раз в три секунды, и
# запускать по два процесса на каждый заход — сорок лишних запусков в минуту
# ради строки, которая меняется раз в месяц.
CHECK_SECONDS = 60

_found = {"at": 0, "engines": {}}


def versions(fresh=False):
    """Какие движки установлены и каких версий.

    Отдаёт словарь вида {"claude_code": "2.1.232", "codex": ""}. Пустая строка
    значит «не установлен»; отдельного поля «нашли или нет» нет намеренно —
    одно значение проще показать и невозможно рассогласовать со вторым.

    Проверка живая, а не однажды записанная в settings.json: движок мог
    исчезнуть после установки — переименовали, снесли, сменили PATH. Спека
    требует, чтобы в этом случае строка в сайдбаре погасла, а бот не падал."""
    now = time.time()
    if not fresh and now - _found["at"] < CHECK_SECONDS:
        return _found["engines"]
    _found["engines"] = {key: version_of(module.COMMAND)
                         for key, module in ENGINES.items()}
    _found["at"] = now
    return _found["engines"]


def version_of(command):
    """`claude --version` одной строкой. Не отвечает — пустая строка.

    Таймаут пять секунд: движок, который думает над `--version` дольше,
    сайдбару всё равно не годится, а держать на нём ответ страницы нельзя.

    stdin=DEVNULL не для красоты: у Codex на открытой трубе — а из-под Flask
    она именно открытая — команда ждёт EOF без конца. Наследие разведки
    2 сентября, где так зависли два прогона по семь и десять минут.

    subprocess только списком аргументов — правило среза 1, здесь тоже."""
    try:
        done = subprocess.run([command, "--version"], capture_output=True,
                              text=True, timeout=5,
                              stdin=subprocess.DEVNULL)
    except (OSError, subprocess.SubprocessError):
        # Чаще всего это FileNotFoundError: команды нет в PATH. Это не
        # поломка бота, а ответ на вопрос «что установлено».
        return ""
    if done.returncode != 0:
        return ""
    first = done.stdout.strip().splitlines()
    return first[0].strip() if first else ""
```

Плюс `import subprocess` и `import time` к импортам `agent.py`.

- [ ] **Шаг 1: Переселить стучавшихся из `state.json` в `settings.json`**

Постучавшийся жил в `state.json`, в списке `refused`, и печатался в терминал
готовой строкой для ручной вставки. Теперь его впускают кнопкой — значит, он
должен лежать там же, где белый список. `state.json` иногда приходится
удалять, когда бот запутался; вместе со служебным файлом человек выкинул бы
очередь на впуск.

В `bot.py` функция `knock()` заменяется целиком (она станет короче — печать
инструкции по ручной вставке уходит вместе с самой ручной вставкой):

```python
def knock(env, message):
    """Чужому отвечаем один раз и запоминаем его в «стучались».

    Настройки перечитываются здесь заново, хотя вызывающий их уже читал:
    между тем чтением и этой строкой хозяин мог нажать «Впустить», и тогда
    человеку незачем слышать отказ.

    Числовой id хранится, но на экран не попадает никогда: показываем ник, а
    если ника нет — имя из профиля и пометку. Ник в телеграме заводить
    необязательно, и человек без ника не должен выглядеть сломанной строкой."""
    sender = message.get("from", {})
    sender_id = sender.get("id")
    settings = config.load_settings()
    if sender_id in config.allowed_ids(settings):
        return
    knocked = settings.get("knocked", [])
    if any(str(person.get("id")) == str(sender_id) for person in knocked):
        return
    knocked.append({"id": sender_id,
                    "username": sender.get("username", ""),
                    "name": sender.get("first_name", ""),
                    "at": time.time()})
    settings["knocked"] = knocked
    config.save_settings(settings)
    print(f"постучался чужой: {who(message)} — впустите его в сайдбаре, "
          "раздел «Кто может писать»")
    say(env["bot_token"], message["chat"]["id"],
        "Этот бот записывает расходы своего хозяина. "
        "Если он вас ждёт — передайте ему, что вы написали.")
```

Единственный вызов, в `admit()`, теряет второй аргумент: было
`knock(env, st, message)`, стало `knock(env, message)`. `import json` в
`bot.py` больше не нужен, если он там больше нигде не встречается — проверьте
`grep -n "json\." bot.py` перед удалением строки импорта.

- [ ] **Шаг 6: Дописать `static/app.js`**

Рядом с остальными помощниками:

```js
  /* Отправка настройки. Ответ несёт свежий снимок состояния, и сайдбар
     перерисовывается им сразу, не дожидаясь ближайшего опроса: три секунды
     между нажатием и результатом ощущаются как поломка, и человек жмёт второй
     раз. */
  function post(path, body) {
    return fetch(path, {
      method: "POST",
      headers: {"Content-Type": "application/json"},
      body: JSON.stringify(body || {})
    })
      .then(function (response) { return response.json(); })
      .then(function (answer) {
        if (answer.state) paint(answer.state);
        return answer;
      });
  }

  /* Одна строка списка. Ник показываем, когда он есть; когда нет — имя из
     профиля и пометку «ника нет»: заводить ник в телеграме необязательно.

     Числовой идентификатор не показывается никогда, хотя работает бот именно
     по нему. Он живёт в замыкании кнопки и уезжает обратно на сервер. */
  function person(record, label, path, hot) {
    var row = el("div", "row");
    row.appendChild(el("span", "k", record.name || "без имени"));
    row.appendChild(record.username
      ? el("span", "v nick", "@" + record.username)
      : el("span", "v noname", "ника нет"));
    var button = el("button", "bt" + (hot ? " go" : ""), label);
    button.type = "button";
    button.addEventListener("click", function () {
      /* Пока сервер думает, второе нажатие впустило бы человека дважды. */
      button.disabled = true;
      post(path, {id: record.id}).then(function (answer) {
        if (!answer.ok) button.disabled = false;
      });
    });
    row.appendChild(button);
    return row;
```

Самая большая задача среза. Токен бота обязан правиться отсюда: репозиторий

- Править: `bot.py`, `config.py`, `web.py`, `templates/workspace.html`,

**Стыки:**
- Берёт: `config.save_env()`, `config.refresh_env()` (задача 1), `post()` и

- Отдаёт: `telegram.call()`, `telegram.check_token()`; маршруты

- [ ] **Шаг 1: Вынести разговор с Bot API в `telegram.py`**

Маршрут «проверить токен» обязан спросить у телеграма `getMe`. Импортировать

```python

Отдельным файлом этот кусок стал, когда токен начали подключать из браузера:
```

Из `bot.py` сюда **переносятся как есть**, вместе с комментариями и

- [ ] **Шаг 2: Разделить опрос и надзор за ним в `bot.py`**

Убить поток в питоне нельзя, а бота меняют на ходу. Поэтому опрос не
останавливают снаружи — он сам смотрит, с тем ли токеном работает.

**Тело нынешней функции `telegram_loop()` переезжает целиком** в новую функцию
`poll_with(env, st, jobs, token)`, вместе со всеми комментариями. Меняются в
нём ровно две вещи:

1. `get_updates(env["bot_token"], st["offset"])` → `get_updates(token, st["offset"])`.
2. Сразу после `except`-ветки, до цикла `for update in updates:`, добавляется:

```python
        # Пока висел долгий опрос, бота могли заменить. Эти обновления от
        # прежнего бота, и двигать по ним offset нового нельзя: у каждого бота
        # своя нумерация, и чужой номер новый бот либо не поймёт, либо поймёт
        # неправильно и промолчит.
        if env["bot_token"] != token:
            return
```

Строка `print("Телеграм: жду сообщений.")` из тела переезжает в надзор ниже —
иначе она не напечатается при замене бота.

На освободившееся имя пишется надзор:

```python
def telegram_loop(env, st, jobs):
    """Надзор за опросом. Живёт всё время работы бота, даже когда токена нет.

    Поток стартует всегда, в том числе с пустым .env: токен может появиться
    через минуту — из мастера или из сайдбара, — и человек не должен ради
    этого перезапускать бота.

    Две секунды сна вместо тридцати не расточительство: пустая проверка стоит
    одно сравнение строк, а полминуты ожидания после нажатия «Подключить»
    человек прочтёт как поломку."""
    while True:
        token = env["bot_token"]
        if not token:
            time.sleep(2)
            continue
        print("Телеграм: жду сообщений.")
        poll_with(env, st, jobs, token)
        print("Телеграм: опрос остановлен — бота заменили или отключили.")
```

- [ ] **Шаг 3: Запускать поток телеграма всегда (`bot.py`, `main()`)**

Функцию целиком не переписываем. В ней сейчас `if env["bot_token"]:` решает,
заводить ли поток опроса. Условие снимается: поток заводится всегда, а решает
уже надзор. Ветка `else` с печатью «Телеграм не подключён — работаем через
браузер» остаётся, но становится обычным `if not env["bot_token"]:` рядом с
запуском потока: сообщение по-прежнему правда, а поток теперь есть.

- [ ] **Шаг 4: Завести ключ `bot` в настройках (`config.py`)**

- [ ] **Шаг 5: Три маршрута в `web.py`**

```python
            return jsonify(ok=False, error=f"Телеграм не принял этот токен: {error}")

            username = telegram.check_token(token)
        except Exception as error:
            return jsonify(ok=False, error=f"Телеграм не принял этот токен: {error}")

        config.save_env({"BOT_TOKEN": token})
        config.refresh_env(env)

        settings = config.load_settings()
        settings["bot"] = username
        config.save_settings(settings)

        st["offset"] = 0
        memory.save(st)
        return jsonify(ok=True, username=username,
                       state=snapshot(env, st, blocked))

    @app.post("/api/telegram/off")
    def telegram_off():
        """Отключить телеграм. Белый список остаётся нетронутым.

        Телеграм опознаёт человека одним номером у всех ботов, и стирать
        список при отключении значило бы наказать хозяина за передумывание.
        Рабочее место без телеграма работает полностью."""
        config.save_env({"BOT_TOKEN": ""})
        config.refresh_env(env)
        st["offset"] = 0
        memory.save(st)
        return jsonify(ok=True, state=snapshot(env, st, blocked))
```

- [ ] **Шаг 1: Убрать выход из `config.load_env()`**

Из функции уходит блок `missing = [...]` вместе с `sys.exit`. Уходит и

```python
def ready(env):
    """Настроено ли главное. Ложь — показываем мастер, правда — рабочее место.

    Главное — это таблица: без неё боту некуда писать, и рабочее место
    показывало бы поле ввода, которое ничего не может.

    Телеграм сюда не входит намеренно: он необязателен, и гнать человека по
    мастеру из-за неподключённого телеграма значит вернуть его на критический

    таблице, было бы наказанием за чужую ошибку. Про исчезнувший движок
    говорит сайдбар и лента, а не мастер."""
    return bool(env["sheet_url"] and env["sheet_secret"])
```

### Задача 7: Клиент мастера — переходы и разговор с сервером

Скрипт мастера пока умеет только переключать экраны. Дадим ему то же, чем
пользуется сайдбар: отправку и показ ответа.

**Файлы:**

- Проверка: консоль браузера, `curl`

**Стыки:**
- Берёт: `go(id)` — уже перенесена задачей 6.
- Отдаёт: `ask(path, body)`; `verdict(id, text)`; экран открывается по
  `/#s-sheet`.

- [ ] **Шаг 1: Дописать отправку в `static/setup.js`**

```js
  /* Разговор с сервером. Тот же вид, что у сайдбара: маршрут латиницей,
     тело — JSON, русские слова едут значениями, а не в адресе.

     Своей ленты у мастера нет, поэтому отказ показывается прямо на экране,
     плашкой под формой. */
  function ask(path, body) {
    return fetch(path, {
      method: "POST",
      headers: {"Content-Type": "application/json"},
      body: JSON.stringify(body || {})
    }).then(function (response) { return response.json(); })
      .catch(function () {
        return {ok: false, error: "Бот не отвечает. Посмотрите окно терминала, " +
                                  "в котором он запущен."};
      });
  }

  /* Плашка с ответом проверки. Один вид у успеха и у отказа намеренно: это
     не «ошибка», а результат проверки, и читать его надо в обоих случаях. */
  function verdict(id, text) {
    var box = document.getElementById(id);
    box.querySelector("span").innerHTML = "";
    box.querySelector("span").textContent = text;
    box.hidden = !text;
  }
```

```python
"""Мастер установки: то, что можно проверить без Flask и без интернета.

Три чистые функции. Первая собирает код для Apps Script с подставленным
секретом. Вторая узнаёт, что за адрес вставил человек. Третья говорит, что
не так со справочником статей.

Две последние существуют потому, что обе ошибки установки, случившиеся при
первой живой настройке, — это ошибки человека, а не программы. Программа
работала правильно оба раза; правильным ответом было бы объяснить.
"""

import re
import secrets
from pathlib import Path

BASE_DIR = Path(__file__).resolve().parent
SCRIPT_PATH = BASE_DIR / "sheet.gs"

# Ровно один раз встречается в sheet.gs, в первой строке, внутри кавычек.
PLACEHOLDER = "__СЕКРЕТ__"


def new_secret():
    """Секрет придумывает машина.

    Придуманный человеком будет либо «12345», либо забыт при вставке во второе
    место. Алфавит token_urlsafe — буквы, цифры, дефис и подчёркивание:
    экранировать в JavaScript нечего, кавычки в коде трогать не нужно."""
    return secrets.token_urlsafe(16)


def script_with_secret(secret):
    """sheet.gs с подставленным секретом — тот текст, который человек скопирует
    в редактор Apps Script.

    Заглушки в файле не нашлось — отказываемся, и это не перестраховка.
    Показать ученику код с __СЕКРЕТ__ внутри значит опубликовать скрипт,
    который пускает любого, кто пришлёт слово __СЕКРЕТ__. Требование
    sheet-setup.md, раздел «Формат подстановки для программы установки»."""
    text = SCRIPT_PATH.read_text(encoding="utf-8")
    if PLACEHOLDER not in text:
        raise ValueError("в sheet.gs нет заглушки __СЕКРЕТ__ — "
                         "не покажу код без секрета")
    return text.replace(PLACEHOLDER, secret)


def address_kind(url):
    """Что за адрес вставил человек.

    В работе их два, и похожи они ровно настолько, чтобы перепутать: адрес
    таблицы (docs.google.com/spreadsheets/…) нужен только чтобы открыть её
    человеку, адрес веб-приложения (script.google.com/macros/s/…/exec) — тот,
    по которому ходит бот. При первой живой настройке 2 сентября в SHEET_URL
    попал первый вместо второго, и вместо ответа пришёл 401.

    Мастер поэтому не подсказывает, а узнаёт. Подсказки «заканчивается на
    /exec» мало: она помогает тому, кто разницу уже понял, а кто не понял —
    видит длинный адрес от Google и считает, что это он и есть.

    Хвост с вопросом и якорем отрезается: Google иногда отдаёт адрес с
    параметрами, и без этого нормальный адрес не прошёл бы проверку на /exec."""
    address = (url or "").strip().split("?")[0].split("#")[0]
    if not address:
        return "пусто"
    if "docs.google.com/spreadsheets" in address:
        return "таблица"
    if "script.google.com" not in address:
        return "чужой"
    if not address.rstrip("/").endswith("/exec"):
        return "без-exec"
    return "веб-приложение"


def categories_verdict(found, expected):
    """Что сказать про прочитанный справочник статей.

    Мастер показывает не «таблица отвечает», а число. Ноль статей означает
    переименованный лист — это ловит сам мост. Пятнадцать вместо шестнадцати
    означает вторую ошибку установки: список вставили с ячейки A1, первая
    статья заняла место заголовка, и мост её законно пропустил.

    Ошибка эта дорогая не сама по себе. Не хватает всегда первой статьи —
    «Продуктов», самой ходовой; опорный тестовый чек это «Пятёрочка», и он
    уезжает в «Прочее» с предупреждением. Приёмка выглядит провалом разбора,
    хотя разбор верен.

    Расхождение в числе само по себе останавливать человека не должно:
    справочник он мог и правда сократить, это его таблица. Останавливаем
    ровно в одном случае — когда прочитанное совпадает с заготовкой без её
    первой строки. Это уже не догадка, а подпись той самой ошибки."""
    count = len(found)
    if expected and found == expected[1:]:
        return {
            "ready": False,
            "count": count,
            "note": f"Прочитано {count} статей, а в заготовке {len(expected)}. "
                    f"Не хватает первой — «{expected[0]}». Так бывает, когда "
                    "список вставили с ячейки A1: первая статья заняла место "
                    "заголовка, и мост её пропускает. Вставьте в таблице "
                    "строку выше первой, напишите в A1 слово «Статья» и "
                    "нажмите «Проверить таблицу» ещё раз.",
        }
    if count != len(expected):
        return {"ready": True, "count": count,
                "note": f"Таблица отвечает. Прочитано {count} статей — в "
                        f"заготовке было {len(expected)}. Если вы правили "
                        "список сами, так и должно быть."}
    return {"ready": True, "count": count,
            "note": f"Таблица отвечает. Прочитано {count} статей."}
```

```js
  /* Строка сводки. Тот же вид, что в карточках сайдбара. */
  function line(key, value) {
    var row = document.createElement("div");
    row.className = "row";
    var left = document.createElement("span");
    left.className = "k";
    left.textContent = key;
    var right = document.createElement("span");
    right.className = "v";
    right.textContent = value;
    row.appendChild(left);
    row.appendChild(right);
    return row;
  }

  /* Сводка на экране готовности. Числа берутся у сервера, а не запоминаются
     по дороге: человек мог поправить таблицу в соседней вкладке, и сводка,
     собранная из ответов десятиминутной давности, соврала бы. */
  function drawSummary(id) {
    fetch("/api/summary")
      .then(function (response) { return response.json(); })
      .then(function (answer) {
        var state = answer.state;
        var card = document.getElementById(id);
        card.textContent = "";
        card.appendChild(line("Движок", state.engine));
        card.appendChild(line("Таблица", state.categories + " статей"));
        card.appendChild(line("Телеграм", state.telegram
          ? "@" + state.bot : "не подключён"));
        if (state.owner) card.appendChild(line("Может писать", state.owner));
      })
      .catch(function () {});
  }
```

```js
  document.getElementById("w-token-check").addEventListener("click", function () {

       перезапустит опрос: без работающего опроса следующий экран ждал бы
       сообщения, которого никто не читает. */

      if (!answer.ok) { verdict("w-token-said", answer.error); return; }
      document.getElementById("w-bot-name").textContent = "@" + answer.username;

          first.username ? "@" + first.username : "ника нет"));

          (first.username ? "@" + first.username : first.name) + "?");

    });
```
