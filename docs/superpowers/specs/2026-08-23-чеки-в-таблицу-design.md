# Чеки в таблицу — дизайн

23 августа 2026. Модуль 6, урок «Создаём своего агента».

## Что делаем

Телеграм-бот, которому присылают фотографию чека или сообщение «такси 450
наличными», а он дописывает строку расхода в Google-таблицу и отвечает, что
записал. Работает на ноутбуке владельца, без сервера и без ключа API: мозгом
служит Claude Code, который уже оплачен подпиской.

Урок про то, что «свой агент» — это файл с инструкцией на человеческом языке
плюс схема ответа. Мозг бота — полторы сотни строк прозы в `prompt.md` и
`schema.json`, и ни строки кода.

Кода при этом около тысячи строк, и **ни одна из них не про понимание чека**.
Весь он про руки: принять, проверить, записать, ответить, не потерять. Это и
есть настоящая пропорция, и она честнее красивой цифры: понимание стоит дёшево
и пишется словами, а надёжность стоит дорого и пишется кодом.

*Поправлено 2 сентября: здесь стояло «меньше сотни строк». К концу среза 1 вышло
1066, и расхождение в десять раз в первом же абзаце обесценивало бы всё
остальное.*

## Границы

**Делаем:** приём фото и текста в личке бота, распознавание, запись строки в
Google Sheets, ответ в чат, раскладка файлов по папкам, честный отказ при
нечитаемом чеке.

**Не делаем:** веб-интерфейса, базы данных, распознавания QR-кода через ФНС,
разбивки чека по позициям, голосовых сообщений, работы 24/7 на сервере,
редактирования уже записанных строк из чата. Всё это — «куда расти» в конце.

## Устройство

Мозг и руки разделены. Агент только смотрит и понимает; всё, что можно
сделать без модели, делается без модели. Это тот же принцип, что в faq-bot, и
здесь он даёт главное: агент физически не может записать строку мимо проверок.

```
Телеграм, личка бота
  ├─ фотография чека ──┐
  └─ «такси 450» ──────┘
           │
           ▼
    bot.py  —  РУКИ
    скачал файл в чеки/входящие/, проверил чат в белом списке
           │
           │  subprocess: claude -p ... --json-schema schema.json
           ▼
    Claude Code headless, по подписке  —  АГЕНТ
    посмотрел на картинку, вернул structured_output
           │
           ▼
    bot.py: детерминированные проверки (дата, сумма, статья)
           │
           ├──► POST в Apps Script ──► Google Sheets: новая строка
           ├──► файл в чеки/готово/ либо чеки/спорные/
           └──► ответ в чат: «Записал: Пятёрочка, 1004,70 ₽, продукты»
```

## Что уже проверено живьём

Эти восемь находок получены прогонами до написания спеки. Реализация должна
опираться на них, а не перепроверять заново.

1. **`--json-schema` работает и возвращает готовый объект.** В ответе
   `--output-format json` появляется поле `structured_output` с уже разобранным
   словарём. Парсить текст руками не нужно.

2. **Русские ключи в схеме запрещены.** API отвечает
   `400 Property keys should match pattern '^[a-zA-Z0-9_.-]{1,64}$'`.
   Поэтому ключи латиницей (`amount`, `merchant`), а значения — русские
   (`"payment": "наличные"`). В перечислениях кириллица разрешена.

3. **`--agent` и `--json-schema` вместе не работают.** При указании `--agent`
   схема молча игнорируется: `structured_output` приходит пустым, модель пишет
   JSON в блоке кода и придумывает свои имена полей (`payment_method` вместо
   `payment`, `currency` теряется). Ошибки при этом не возникает — поломка
   тихая, и её легко не заметить.
   **Решение: мозг агента лежит в `prompt.md` и подключается через
   `--append-system-prompt`.** Эта связка со схемой работает.

4. **Картинки читаются.** Достаточно `--allowedTools Read` и
   `--permission-mode acceptEdits`. Никаких OCR-библиотек, tesseract и прочего.

5. **Модель имеет значение.** На мятом чеке haiku в одном прогоне из четырёх
   прочитал дату 20.08 как 20.09, поставив себе уверенность «высокая».
   На обрезанном чеке haiku в одном прогоне из трёх подставил видимую сумму
   позиции вместо честного «не знаю». Sonnet в обоих случаях отработал верно
   во всех прогонах. Отсюда: **фото — sonnet, текст — haiku**.

6. **Один и тот же файл читается по-разному.** Это не поломка настройки, а
   свойство модели, и оно определяет весь подход к проверкам: нельзя ни
   «проверить один раз и успокоиться», ни полагаться на самооценку уверенности.
   Проверки в коде должны срабатывать всегда, а не только когда агент
   признался, что сомневается.

7. **Один вызов стоит около 33 тысяч токенов и 15–50 секунд.** Токены уходят
   на системный промпт сессии, а не на сам чек, поэтому текстовое сообщение
   стоит почти столько же, сколько фотография.

8. **Тестовые чеки — в JPEG.** Телеграм отдаёт боту именно его. На PNG те же
   файлы читались иначе: часть ошибок появилась только после сжатия, часть
   наоборот исчезла. Проверять надо в том формате, в котором придёт боевой чек.

## Файлы проекта

```
чеки-бот/
  prompt.md                     мозг агента: что искать в чеке, когда не угадывать
  schema.json                   поля ответа, ими же ответ и валидируется
  categories-seed.md            стартовый список статей — вставляется в лист «Статьи»
                                на уроке; в работе бота не участвует
  agent.py                      вызов Claude Code и разбор ответа
  bot.py                        телеграм: приём, проверки, запись, ответ
  sheet.gs                      код для Apps Script, вставляется в таблицу
  .env                          токен бота, адрес таблицы, секрет, белый список
  .env.example                  то же самое без значений
  state.json                    offset телеграма и уже обработанные файлы
  чеки/входящие|готово|спорные/
  тестовые-чеки/                чёткий, мятый, обрезанный + примеры текстом
  tools/make_receipts.py        генератор тестовых чеков
```

Копия мозга агента лежит ещё и в `.claude/agents/expense-reader.md` — чтобы
его можно было позвать руками из интерактивной сессии, когда отлаживаешь
формулировки. Боевой путь идёт через `prompt.md` (см. находку 3).

Код и имена файлов латиницей, как в faq-bot. Русский — в текстах, промптах,
названиях папок с чеками и колонках таблицы.

## Схема ответа агента

Все поля обязательные — иначе схема не заставит модель их заполнить.

| Поле | Тип | Смысл |
|---|---|---|
| `intent` | `расход` `правка` `не расход` | Что это вообще? На «привет» и меню — «не расход», на «не 450, а 480» — «правка» |
| `date` | строка | `ГГГГ-ММ-ДД`, либо пустая строка |
| `amount` | число или `null` | Итог. Не прочиталось — `null`, не угадывать |
| `amount_source` | `строка ИТОГ` `строка К ОПЛАТЕ` `сложены позиции` `не нашёл` | Откуда взято число. Наблюдение, а не оценка |
| `currency` | `RUB` `USD` `EUR` `другая` | |
| `merchant` | строка | Вывеска с чека или суть из сообщения |
| `category` | строка | Ровно одна строка из справочника на листе «Статьи» |
| `payment` | `карта` `наличные` `перевод` `неизвестно` | |
| `confidence` | `высокая` `средняя` `низкая` | |
| `doubts` | строка | Что именно не прочиталось |
| `reply` | строка | Одна фраза человеку в чат |

## Таблица

Два листа. Первый — «Расходы», куда бот пишет. Второй — «Статьи», откуда бот
читает справочник.

### Лист «Расходы»

Одиннадцать колонок:

`дата операции` · `сумма` · `валюта` · `продавец / на что` · `статья расхода` ·
`способ оплаты` · `источник` · `кто прислал` · `статус` · `файл` · `записано`

`источник` — «фото чека» или «текст». Через месяц станет важно, что из этого
подтверждено бумажкой, а что записано со слов.
`статус` — «готово» или «проверить».
`файл` — имя файла в папке `готово/` или `спорные/`, чтобы можно было поднять
оригинал.

### Лист «Статьи»

Одна колонка, по строке на статью. Правится хозяином таблицы без участия
программиста и без перезапуска бота: следующий же чек разберётся по новому
списку.

Это не украшение, а суть: справочник статей — рабочий инструмент финансиста,
и он должен лежать там, где финансист работает. Держать его файлом внутри
проекта означало бы, что за каждой новой статьёй расхода надо идти в редактор
кода.

Первая строка — заголовок «Статья», он пропускается. «Прочее» обязано быть
в списке: в него уезжает всё, что агент не смог отнести никуда.

### Мост

Apps Script, привязанный к самой таблице и опубликованный веб-приложением.
Он умеет две вещи: принять строку (`doPost`) и отдать справочник (`doGet`).
Google Cloud, сервисные аккаунты и файлы с ключами не нужны.

```javascript
const SECRET = 'придумайте-свою-строку';

function doPost(e) {
  const d = JSON.parse(e.postData.contents);
  if (d.secret !== SECRET) return reply({ok: false, error: 'нет доступа'});

  const sheet = SpreadsheetApp.getActiveSpreadsheet().getSheetByName('Расходы');
  sheet.appendRow([
    d.date, d.amount, d.currency, d.merchant, d.category,
    d.payment, d.source, d.who, d.status, d.file, new Date()
  ]);
  return reply({ok: true, row: sheet.getLastRow()});
}

function doGet(e) {
  if (e.parameter.secret !== SECRET) return reply({ok: false, error: 'нет доступа'});

  const sheet = SpreadsheetApp.getActiveSpreadsheet().getSheetByName('Статьи');
  const categories = sheet.getRange('A2:A').getValues()
    .map(function (row) { return String(row[0]).trim(); })
    .filter(function (v) { return v.length > 0; });
  return reply({ok: true, categories: categories});
}

function reply(o) {
  return ContentService.createTextOutput(JSON.stringify(o))
    .setMimeType(ContentService.MimeType.JSON);
}
```

Публикация: Расширения → Apps Script → Развернуть → Веб-приложение,
«Запуск от имени: я», «Доступ: все». Полученный URL идёт в `.env`.

Отдельно: адрес веб-приложения — это и есть ключ от таблицы. Кто его знает,
тот может дописывать строки. Поэтому и в POST, и в GET идёт ещё и `secret`,
а сам URL не показывается на экране во время урока.

Замечание по реализации: веб-приложение Apps Script отвечает редиректом на
`script.googleusercontent.com`. `requests` переходит по нему сам, но заголовок
`allow_redirects` отключать нельзя — иначе вместо ответа придёт пустой 302.

## Поток обработки

**Фотография.** Бот получает `photo`, берёт самый крупный размер, спрашивает
`getFile`, скачивает в `чеки/входящие/` под именем `ГГГГ-ММ-ДД_ЧЧММСС_кто.jpg`.
Отвечает в чат «Смотрю чек…», потому что ответа ждать 15–50 секунд. Зовёт
агента на sonnet. Дальше — проверки и запись.

**Текст.** Ничего не скачивается, сообщение уходит агенту как есть, моделью
берётся haiku. В задание подставляется сегодняшняя дата, иначе «вчера» и «в
пятницу» не во что превратить.

**Задание агенту** собирается из трёх кусков: сегодняшняя дата, сам вход (путь
к файлу или текст сообщения) и справочник статей. Мозг из `prompt.md` уходит
в `--append-system-prompt`.

**Справочник статей** бот забирает у таблицы запросом `doGet` перед разбором.
Список кэшируется на пять минут, чтобы не дёргать таблицу на каждое сообщение,
и одновременно сохраняется в `state.json` — это запасной вариант на случай,
когда таблица недоступна. Правка списка в таблице подхватывается сама, без
перезапуска бота: следующий чек после истечения кэша разберётся по-новому.

Вызов делается через `subprocess.run` со списком аргументов. Через строку в
шелле нельзя: в промпте есть кавычки и обратные кавычки, и шелл на них
спотыкается — проверено.

## Проверки без модели

Всё это делает `bot.py` сам, и именно это спасает от уверенных ошибок агента.

- **Дата в будущем** — статус «проверить», какой бы ни была уверенность.
  Именно так ловится ошибка из находки 5: агент прочитал 20 сентября, когда
  на дворе 23 августа.
- **Дата старше года** — тоже «проверить».
- **Даты нет** — «проверить».
- **Суммы нет или она не больше нуля** — «проверить», файл в `спорные/`.
- **Сумма больше 100 000 ₽** — «проверить». Крупная трата стоит взгляда, даже
  если чек читался идеально.
- **Уверенность низкая** — «проверить».
- **Продавца нет** — «проверить». Колонка называется «продавец / на что», и пустая
  она оставляет в таблице строку «2 сентября, 12000, Прочее»: такую трату через месяц
  не найти и не оспорить. Проверка добавлена 2 сентября: до неё «заплатил 12000»
  уезжало как «готово», а «проверить» получалось только когда агент сам признавал
  неуверенность — то есть статус висел на `confidence`. Способ оплаты при этом
  специально не проверяется: «неизвестно» — законное значение, «кофе 300» не обязано
  говорить, чем платили.
- **Сумма есть, а взялась она не из итога** — `amount_source` равен «не нашёл» или
  «сложены позиции» — «проверить», независимо от заявленной уверенности. Это главная
  проверка на выдумку, и добавлена она 2 сентября по итогам прогона: `03-обрезанный`
  вернул 1819,20 (видимую позицию вместо неизвестного итога), уверенность поставил
  высокую и прошёл насквозь. Порознь «сумма 1819,20» и «итога не видел» выглядят
  невинно; ловит их противоречие между ними.
  Заметьте, чем этот вопрос отличается от вопроса об уверенности: «откуда число» —
  наблюдение, его модель делает тем же действием, что и чтение суммы. «Насколько ты
  уверен» — отдельная способность, которой у модели нет. Ни одна проверка по-прежнему
  не спрашивает агента, уверен ли он; правило только уточнилось.
- **Статьи нет в справочнике** — заменяется на «Прочее», в чат уходит
  предупреждение с тем, что вернул агент. Это не редкость, а рабочий сигнал:
  значит, в справочнике не хватает статьи, и хозяин таблицы допишет её строкой
  на листе «Статьи».
- **`intent: не расход`** — в таблицу не пишем вообще, в чат уходит `reply`.
- **`intent: правка`** — в срезе 1 не обрабатывается: в чат уходит «правки пока
  не умею». Оживает в срезе 3 (см. спеку «Рабочее место»).

Файл едет в `готово/` только при статусе «готово», иначе в `спорные/`.

## Ошибки и отказы

- **Агент не ответил за 180 секунд** — вызов снимается, одна повторная
  попытка, потом в чат «не смог разобрать, попробуйте ещё раз или напишите
  текстом». Файл остаётся во `входящих`.
- **`is_error: true` в ответе** — то же самое.
- **`structured_output` пустой** — признак, что схема отвалилась (находка 3).
  В журнал пишется полный ответ, в чат — честный отказ. Молча парсить текст
  из блока кода нельзя.
- **Таблица не ответила или вернула не `ok`** — строка складывается в
  `state.json` в очередь и уходит при следующем удачном запросе. Человеку
  говорится «распознал, но в таблицу не попало, попробую позже».
- **Справочник не читается** (таблица недоступна, лист переименован, пустой
  ответ) — берётся последний список из `state.json`. Если и его нет — бот
  отказывается разбирать и говорит человеку, что не видит справочник статей.
  Придумывать статьи самому агенту нельзя: в отчёте заведутся «Продукты»,
  «Продукты питания» и «Еда» вместо одной строки.
- **Телеграм не отвечает** — пауза и повтор, offset не двигается.
- **Одно и то же фото прислали дважды** — ловится по `file_unique_id`,
  сохранённому в `state.json`. Второй раз в таблицу не пишем, отвечаем
  «этот чек уже записан».

`state.json` хранит три вещи: offset телеграма (чтобы после перезапуска не
разбирать всё заново), список уже обработанных файлов и последний прочитанный
справочник статей.

## Безопасность

- **Белый список чатов** в `.env`. Бота найдут по имени, и посторонние строки
  в таблице никому не нужны. Чужому отвечаем один раз и молчим дальше.
- **Секрет для Apps Script** — в теле POST, не в URL.
- **`ANTHROPIC_API_KEY` не должен быть задан.** Если он завалялся в окружении,
  Claude Code пойдёт по счётчику вместо подписки, и человек узнает об этом из
  счёта. `bot.py` при старте проверяет переменную и отказывается запускаться,
  печатая, что делать.
- `.env` в `.gitignore`, права `600`.

## Деньги и лимиты

Оплата — только подписка Claude, за неё уже заплачено. Телеграм и Apps Script
бесплатны. Ключ API не заводится.

Ограничение в другом: около 33 тысяч токенов на вызов. Десяток чеков за вечер
незаметны; двести подряд упрутся в лимит подписки. Лечится склейкой — бот
ждёт десять секунд тишины и отдаёт накопившееся одним вызовом. В первой версии
не делаем: по одному чеку нагляднее на уроке. Записано в «куда расти».

## Как проверяем

Живьём, без автотестов — проект слишком мал, чтобы городить pytest, и урок не
про это.

1. Три тестовых чека из `тестовые-чеки/` через `agent.py` из терминала,
   **по два-три прогона каждый**. Ожидание: чёткий и мятый разобраны верно,
   обрезанный даёт `amount: null` и низкую уверенность. Расхождения между
   прогонами нормальны — ненормально, когда проверки их пропускают.
2. Пять текстовых примеров оттуда же, включая «привет» — должен получиться
   отказ с подсказкой.
3. Присылаем те же файлы боту в личку: строки появляются в таблице, файлы
   расходятся по `готово/` и `спорные/`.
4. Присылаем один и тот же чек дважды — второй раз строки нет.
5. Пишем в бота из чужого аккаунта — строки нет.
6. Гасим интернет на середине — бот не падает, при возврате сети строка
   доезжает.
7. Дописываем статью на лист «Статьи» и через пять минут шлём подходящий
   расход — он попадает в новую статью без перезапуска бота.
8. Переименовываем лист «Статьи» — бот работает на кэше и говорит об этом,
   а не пишет строки с выдуманными статьями.

## Запуск

```bash
cd чеки-бот
python3 -m venv .venv
.venv/bin/pip install requests python-dotenv
cp .env.example .env      # токен бота, адрес таблицы, секрет, свой chat_id
chmod 600 .env
.venv/bin/python bot.py
```

Бот работает, пока открыт терминал. Закрыли ноутбук — бот молчит, сообщения
копятся в телеграме и разберутся при следующем запуске: offset никуда не
делся.

## Куда расти

Порядок — по отношению пользы к труду.

1. **Склейка вызовов.** Пачка чеков за один запрос вместо десяти запросов.
2. **Эскалация модели.** Сначала haiku, и только при низкой уверенности —
   повтор на sonnet. Экономит лимит на простых чеках.
3. **Правка из чата.** «Не 3200, а 3400» — бот находит свою последнюю строку
   и исправляет.
4. **Месячная сводка.** Раз в месяц бот присылает, сколько и на что ушло —
   разбивка как раз по листу «Статьи».
5. **Круглосуточная работа.** Тот же `bot.py` на VPS под systemd, как faq-bot.
6. **Голосовые.** «Заправился на три двести» — упирается в расшифровку речи,
   которой в подписке нет.
